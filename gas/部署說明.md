# 逐層掘進 · Google Apps Script 部署說明

## 一、這套系統在做什麼

一句話：**讓學生在跟老師一次次的交付與驗收之間，學會專案管理。**

系統把一學期的專題課變成從地表挖到地心的五層洞窟。老師在每一層開任務清單，學生逐項交付、逐項被確認，全層通過才送關卡、才拿到往下一層的道具。真正在教的東西發生在來回之間——學生說「我覺得我做到了、這一項花了多少力氣」，老師說「憑什麼算通過、還缺哪一塊」。那一來一往就是教材。

**全收集是核心。** 每一層的礦脈是固定的（6/6/5/5/1，全部 23 塊），每一塊本來就對應一項工作。老師要把那一層的礦脈開完，學生要把那一層採完，才拿得到那一層的道具、通過這一層——沒有「可選」的東西，沒有捷徑，圖鑑最後一定是滿的。走完地心那一頁不是感想文，是把他們做過的事說清楚：一個專案，從頭帶到尾。這件事他們已經做過一次了，接下來的期末發表就是同一件事再做一次。

`design_handoff_zhuceng_juejin` 交付包裡的原型畫面、文案、五層內容、23 塊礦物、五支道具、六件寶物**逐字沿用**，沒有改寫。這一版把它做成可以真的開學就用的系統。

## 二、檔案

| 檔案 | GAS 類型 | 內容 |
|---|---|---|
| `Code.gs` | 指令碼 | 全部 API、Sheets 讀寫、Drive 繳交檔案、延遲揭露、匯出匿名 |
| `Index.html` | HTML | 單頁外殼 |
| `Styles.html` | HTML | Cubic 11 字型、keyframes、reset |
| `Sprites.html` | HTML | 41 張 PNG 的 base64 |
| `Template.html` | HTML | 原型模板 |
| `Runtime.html` | HTML | 約 250 行的最小渲染器 |
| `Logic.html` | HTML | 原型的 `class Component`，原封不動 |
| `Live.html` | HTML | 整合層：登入、真實資料、所有實際使用版的行為 |
| `appsscript.json` | 資訊清單 | 時區、權限、網頁應用程式設定 |

## 三、部署

1. <https://script.google.com> → 新增專案。
2. `Code.gs` 內容整個換掉；其餘七個用「檔案 ＋ → HTML」新增，**檔名不加 `.html`**（`Index`、`Styles`、`Sprites`、`Template`、`Runtime`、`Logic`、`Live`）。
3. 專案設定勾「顯示 appsscript.json」，貼上內容。
4. 執行函式 `setup` → 授權。會建好資料表與「逐層掘進 · 繳交檔案」資料夾。
5. 部署 → 網頁應用程式 → 執行身分**我**、存取權**所有人**。

> 用 `clasp` 就直接 `clasp push` 這個資料夾。
> 改完程式碼要「管理部署作業 → 編輯 → 版本選『新版本』」才生效。
> **如果你之前部署過舊版**：欄位有增加，請再執行一次 `setup`，並執行 `resetClassData` 清掉舊的課堂資料（帳號會保留）。

## 四、開學前你要做的事（研究者）

打開網址 → 出發 → 選「研究者」→ 下一步 → **「第一次使用？註冊研究者帳號」**。
只有研究者與學生能自行註冊，老師的帳號由你發。

註冊完進 `ADM 帳號管理`，由上往下做：

### 1. 揭露節奏
預設**每週都看得到**（研究要每週做）。想改回原設計的「每四週解鎖一次」也在這裡按。

### 2. 開班
填班級名稱、學期、**開課日（第 1 週的週一）**、**總週數**。
→ 一學期 18、一學年 36、整整一年 52、兩年 104，**最多 156 週（三年）**。總週數決定甘特圖有幾欄、期限可以訂到第幾週；開完之後在下面每一班那一列還可以改。
→ **跨年度的專案照樣可以開**：甘特圖的格寬會依週數自動縮（≤24 週用寬格、≤60 用中格、更長用窄格），學生端另有寬／中／窄與「跳到本週」；老師端的期限快選在長課程只列現在前後十週，更後面的直接用日期挑，系統自動換算週次。
→ 「學期第幾週」就是從這一天依真實日期自動算的，之後老師可以手動覆寫。
→ 開完會拿到一組**班級邀請碼**，發給學生。

### 3. 貼名單
把你拿到的分組名單貼進去，一行一組：

```
挖到再說：陳小明, 李小華, 張大同
慢慢掘：王小美, 林小強
```

按「建立／更新名單」→ 小隊直接開好，名字也定好了。
下面會列出每一組每一個名字，標著「還沒註冊」或「已認領（誰的帳號）」。點「放掉」可以把認錯的名字釋放出來重選。

### 4. 建老師帳號
選「老師」＋班級，填姓名、帳號、初始密碼 → 抄給老師。

## 五、學期中

### 學生

用邀請碼**自己註冊**（帳號＋密碼），註冊完會進「**你是誰？**」，在名單裡點自己的名字就進到對的組。姓名是你定的，學生不能自己打。

**開頭的故事五頁**：信與地圖 → 出發 → 荒原上的斗篷人 → **路上不是空的**（每一層深處都站著一隻東西，長得就是那一層最難的那件事）→ **斗篷人手上有能打倒牠的東西**（他要的是礦石，這一層的每一塊；採齊了去跟他申請，他點頭才鑄得成道具）。老師端的「作品的故事 · 三」講同一件事，從他那一側說。

之後：

- **S-01 首頁**　最上面就是「這一層怎麼走」四步：排時程→說你哪一週交 ／ 交任務→採礦石 ／ 這一層採齊→送關卡 ／ 老師審核→交出道具與寶物，每一步標著現在的進度。下面接「下一件要做的事」，只講一件，附一顆直接跳過去的按鈕。
- **S-02 任務清單**　依狀態切成四個獨立區塊（要補的／還沒交／等他驗收／已完成），每一列標已採或待採。
  - **已經開工或已通過**的項目才會顯示「這一項通過會採到什麼物證」；還沒開始的維持 `？？？`。
  - **採集進度**：這一層的礦脈有幾塊、老師開了幾塊、你採到幾塊、還差幾塊、下一塊是哪一個。礦脈沒開完的時候會直接說「還有 N 塊沒開，去問他剩下的什麼時候給」。
- **關卡送審**　三題：你在這一層的路上做了什麼事情 ／ 你覺得你們在這階段有什麼變化 ／ 接下來要做什麼事情。上方先說明為什麼問這三題。
- **S-03 地圖剖面**　前四層的通道最後站著**那一層的守關生物**（像素圖直接畫在層底）：還沒到的層是暗影＋？？？，現在這一層採齊之前是暗的、採齊後亮起並浮動，**通過之後牠就消失**，格子換回打勾的關。第五層沒有生物，維持「關」。點牠＝點關卡格，被擋時牠會先說一句自己的台詞。
- **S-03 收藏總覽**　四組：道具 5 · 寶物 5 · 礦物 23 · **守關生物 4**。前三組維持原本的規則；守關生物是前四層各一隻（霧面者／千晶母／擬聲者／漲潮者），**通過那一層才解鎖**，點進去讀得到牠的樣貌、牠是哪一種專案失敗模式、剋牠的是哪一件道具。第五層沒有生物——那一層擋你的是你自己。老師端不上鎖，四隻全部可讀。
- **S-05 提交**　順序是：**要提交的東西**（截圖／文件／影片／連結，擺最前面，上面就是老師寫的檔案規格）→ **提交內容**（交出來的是什麼、做到哪個程度）→ **這一組現在的狀態**（必填，三選一：比預估快／差不多／慢；只有勾「比預估慢」才要寫一句為什麼）→ 現在卡在哪（可留空）→ 送出。
  - 截圖／文件／影片會**真的上傳到課程的雲端硬碟**，只有自己組和老師看得到；單檔 10 MB。更大的用「連結」。
- **甘特圖**　欄位依這一班的實際學期長度（預設 18 週，可調）。點一格＝那一週交，同一列再點第二格就拉成一段區間。排程老師看不到。
  - **排程是主流程的一環，不是可選的**：每一項都要先說「打算哪一週交」才交得出去，前端擋、後端也擋。
  - **一年以上的專案**：上方會標「104 週（約 2 年）· 現在第 N 週」，右邊有**寬／中／窄**與**跳到本週**。期末回顧的整學期比對圖也會跟著縮，並自動疏化週次標籤。
  - 不想跳去甘特圖也可以——**S-05 提交頁上方就有週次快選**，沒排過的會標紅「還沒排」，點一顆就排好。排過的顯示你當初排的那一週、現在第幾週、差幾週。
  - S-01 的「下一件要做的事」在清單剛發下來、一項都還沒排的時候，會先叫你去排整層。
- **期末回顧**　側欄一開始是一項 `？？？`，點不進去。**走完第五層還不夠——要老師放行，它才會亮成「結局」。** 這是那個 `？？？` 伏筆的答案：它不是自動開的，是他開的。
  - 最上面是**他放行時說的那段話**（標著「他放你們進來的時候說（老師名）」）——這是學生在結局讀到的第一句。
  - 接著是**故事結局四頁**：牆是空的（四件寶物帶到星核聖殿）→ 空冠復原 → 斗篷人最後的話（「重要的是你為了湊齊它做過的那些事」）→ 第五層那一塊礦石的命名。故事在這裡收完，才接數字。
  - **沒放行就寫不了最後三題**，後端也擋。
  - 最上面直接說明他們剛剛做完的事是什麼：**「一個專案，從頭帶到尾」**——把大事拆成做得完的項目 ／ 排出順序、估時間、交出去 ／ 被退回、修好、再交一次。這就是專案管理，接下來的期末發表他們做得來。
  - 頁面內容：空冠復原（四件寶物歸位）＋斗篷人最後的台詞、整學期採到什麼、**整學期的「你排的 對 實際發生的」**（一項一列，○ 是當初排的、● 是實際通過，紅＝比排的慢、琥珀＝比排的快，並算出前兩層與後幾層的平均誤差有沒有縮小）、自評準確度、以及最後三題。
- **S-03 地圖 · 圖鑑**　**通道直接畫在剖面上**：每一層底部鋪著自己那一段礦脈（L1 六塊、L2 六塊、L3 五塊、L4 五塊、L5 一塊，共 23 塊），層末一格是「關」。**一格＝一塊礦石＝一項工作**，格子上寫著名字（採到了顯示礦石名，還沒採到顯示老師寫的項目名），**點下去直接跳到那一項的提交頁**。還沒到的層壓暗。右上角標著**同一層還有哪幾組**，點名字就讀他們的通過紀錄（會記錄閱讀事件）。點某一層看那一層的道具與寶物；「收藏總覽」是完整圖鑑（道具 5、寶物 5、礦物 23）。沒到的層、沒拿到的東西一律 `？？？`。
- **S-06 道具／寶物介紹**　介紹下面直接列出**要湊齊哪些礦石才拿得到它**：一格一塊，標對應哪一項任務、採到沒有（✓／…／!），上面標著 `3 / 5 塊`。老師還沒開這一層清單時，改列這一層礦脈裡可能出現的礦石。還沒開工的項目仍然是 `？？？`。

### 老師

- **T-01 待你驗收**　依各組**停留週數**排序，不是先交先看。每一組一張卡，標著有幾件等你驗收、以及這一批的樣子（幾件逾期、幾件他們自己覺得比預估慢）。點卡片直接鎖定那一組。
- **T-03 → T-06 逐項確認**　**一次審完一組，不是一項一項跳。**
  - T-03 先把待審件收攏成組：「待審的 6 件收攏成 3 組」。點一組，那一組的東西一起攤開，上面標著這一批的樣子（幾件逾期、幾件他們覺得比預估慢、幾件寫了卡在哪）——**跨項的問題只有一起看才看得出來**。
  - T-06 標著「第 2 件 / 共 3 件」，寫完一件**自動接下一件**，不用回清單；也可以用「← 上一件 / 下一件 →」跳。這一組審完才回到組別清單。
  - 先看到**他們對自己的判斷**（快／準／慢＋原因＋卡住的地方），再寫合格考量。系統會依他們的自評給你一句提示，快選起頭句也包含回應自評的兩句。附件可以直接點開。
  - **你自己的常用句**：你寫過三次以上的開頭會變成快選（標著「用過 N 次」）。是你的話，不是系統的罐頭——點一下帶進去，後面還是要你寫。
  - **書寫量對照**：「你在這一層平均寫 19 字，上一層是 40 字」。不強制長度，但讓變化被自己看見。短了很多會多問一句「是有意識的嗎」。
- **T-04 全班位置**　地圖剖面／收藏總覽／班級名單三個並排分頁，不再堆在同一頁往下捲。
- **切換班級**　獨立畫面，每一班一張卡，含邀請碼與目前週次。
- **T-05 撰寫任務**　最上面「怎麼用這一頁」講清楚節奏：**一次寫一項 → 按「＋ 加入清單」→ 欄位清空、接著寫下一項 → 這一層全部寫完再按「發派給全班（N 項）」整份一起送出**。按鈕上方就是草稿清單，寫幾項就疊幾項，還沒發派前隨時可以拿掉。
  - **建議一層一層開**：這一層快開始的時候再開這一層——你已經看過上一層他們實際卡在哪，這一層的清單才開得準。想先把後面幾層草擬起來也可以，學生只看得到自己所在的那一層，先開不會劇透，之後在 T-02 隨時還能改。
  - 上面先說「你現在在開的是什麼」：你開的每一項＝學生要採的一塊礦石 → **這一層開的全部採齊**，他們才送得出關卡 → 你在 T-07 才交出道具與寶物。下面即時顯示已發派幾項、草稿幾項、他們要採齊幾塊、這一層礦脈總共幾塊。
  - **沒有必要／延伸的分別了**，也沒有「開幾項」這個選擇：**這一層的礦脈有幾塊，你就要開幾項**。上面的數字列即時標「這一層的礦脈 6 塊 ／ 你開了 4 塊 ／ 還沒開 2 塊」，沒開完會用紅字點名還缺哪幾塊、並提醒學生現在過不了這一層。
  - 下面的**「這一項是哪一塊礦石」**就是那一層的礦脈清單，標著 `(4 / 6 已開)`。每一塊礦石本來就對應一項工作（例：定名石＝專案定義、裂晶＝任務拆分），**你要寫的是這一班的通過條件**，不是重新發明要交什麼。已經開過的會標「已配給」，點不下去。
  - 還可以寫「要交的檔案與規格」（有五顆快選），學生在提交頁看得到。
  - 期限可以按週次快選（涵蓋整個學期）、選任一個星期幾，或**直接挑一個日期**——系統自動換算成「W幾 · 月/日（週幾）」。
  - **撞週警告**：訂期限的當下就算給你看——「這一層有 4 項都訂在第 3 週。班上有 6 組，那一週你會同時收到 24 件。」下面列出每一週各幾項、會變成幾件。**尖峰是在開清單的時候造出來的，就要在這時候擋。**
  - 桌機是**左右兩欄**：左邊寫，右邊固定跟著捲的側欄放草稿清單與兩顆按鈕。頁面最上面一條橫幅只有兩句說明，下面一排數字（已發派／草稿／過關門檻／礦脈總數）即時跳。
- **T-07 關卡審核**　多組同時送審時上方有切換列。那一層沒採齊會直接標出「還不能放他們過關」與缺哪幾塊。
- **T-09 期末回顧**　**這是老師在系統裡的最後一個動作：准許進入結局。** 五層全過的小隊會出現在這裡（不用等他們先寫——他們還寫不了）。
  - 那一組整學期的紀錄：通過幾項、交了幾次、你退回幾次、排程平均誤差、幾項比排的晚，加上他們寫的三題原文。
  - 順序是：**你讀完他們整學期的紀錄 → 寫下要說的話 → 按「准許進入結局」→ 他們側欄那個 `？？？` 才會亮 → 他們讀完結局，寫最後三題 → 你回來這一頁讀他們寫的**。
  - **沒寫話放行不了**，後端會擋——那一段是他們在結局讀到的第一句，不能空著。
  - 放行之後這一頁改標「已放行 · 等他們寫」／「已放行 · 他們寫完了」，按鈕變成「改一下這段話」，隨時可以改。
  - 學生重送三題不會洗掉你的放行與那段話。

### 研究者

## 七、核心規則（系統會擋，不是只寫在說明裡）

- **全收集**（兩道，缺一不可）：
  1. **礦脈要開完**：第一層有 6 塊，老師只開 4 項的話學生就過不了——後端擋學生送審，也擋老師放行，並點名還缺哪幾塊。
  2. **礦石要採完**：那一層開出來的每一塊都要通過。少一塊就送不出關卡。
  兩道都過了才換層。所以整學期走完，23 塊圖鑑一定是滿的。

- **課程長度**：2–156 週（最長三年）。甘特圖、期限、期末比對圖都跟著這個數字走。

- **排程也是主流程**：每一項都要先排過「打算哪一週交」才交得出去。有估過，期末回顧的「你排的 對 實際發生的」才有東西可以對照——那張表就是整套系統要學生看見的東西。
- **逾期只標示不阻擋**：仍可提交、仍可確認、仍計入等級。
- **逾時自動暫准（老師缺席時，成本不由學生承擔）**：交出去（或關卡送出）超過 **7 天**沒被驗收，任何人下一次開頁面時系統就先放行——逐項會標成通過、寫上「（逾時自動暫准）」的說明，老師回來重新驗收時那段字會換成他寫的。關卡的自動放行**仍然要過全收集的兩道門檻**，沒採齊就留給老師。天數在資料庫 Config 表的 autoDays 改。自動放行的紀錄在 Reviews（result=auto）與 Passes（verdict=auto）裡，研究端對照用；自動暫准的關卡**不會**出現在他組的公開紀錄裡。
- **道具與寶物不是同一件事**：**道具是武器**——用這一層的礦石鑄成，剋的正好是這一層的守關生物；老師通過關卡＝礦石鑄成道具＝牠退開，一層一件。**寶物**是老師看你們這一層做得怎麼樣才給的，它衡量的是品質，不是有沒有交完。道具的 S-06 介紹頁會寫「它剋的是誰／鑄造的方式／怎麼來的」。
- **迷霧規則**：沒抵達的層只顯示深度與 `？？？`；沒開工的任務不預告會採到什麼；寶物通過才知道是什麼。
- **排程老師看不到**：甘特圖只在學生端。
- **沒有等級、沒有分數**：沒有工具階級這種東西，也沒有排行。系統只記錄「採到幾塊、什麼時候採到、老師憑什麼判斷」。
- **一項一定對到一塊礦石**：老師沒選的話系統會自動配一塊還沒用掉的，不會出現「開了 1 項但礦脈還缺 6 塊」這種對不起來的數字。
- **提交頁的順序**：要交的東西（檔案、連結）擺最前面，接著寫「提交內容」，最後才是問你們自己的那一段。「這一組現在的狀態」三選一是必填；只有勾「比預估慢」的才要寫一句為什麼。

## 八、已知限制

- 單檔上限 10 MB；影片建議用連結。檔案存在**部署者**的雲端硬碟，權限由系統自己擋（同組學生＋該班老師；研究者看不到內容）。
- 多人同時改同一筆是後寫的贏；寫入有 `LockService` 保護，但沒有欄位級合併。
- 畫面每 30 秒輪詢一次（分頁在背景或正在打字時不打擾）。**輪詢先問一支很便宜的 apiPing**：資料沒動就不抓整包，一個班同時掛著幾十個分頁也不會把 Apps Script 的配額吃掉。
- **讀取快取**：後端讀資料表先走記憶體與 CacheService（寫入即作廢、日期以本地時區存字串），一次 bootstrap 從十幾趟試算表往返降到接近零。這是整班同時使用時不會出現「同時執行數過多」的關鍵。
- 研究者端只在桌機顯示，這是設計上的限制。
- 課程最長 156 週（三年）。再長的專案要拆成兩個班分別開。
- Cubic 11 字型走 jsDelivr CDN，第一次載入需要連外網。

## 九、Firebase 版（正式版後端搬到 Firestore）

同一份 `Code.gs`，兩個地方都能跑。**商業邏輯一行都沒改**——48 支 API、130 道檢查、兩道全收集關卡完全相同，換掉的只有底下那層儲存。

### 對應關係

| Apps Script | Firebase |
|---|---|
| 試算表 15 張工作表 | Firestore 15 個 collection（一列 = 一份文件） |
| `DriveApp` 繳交檔案 | Cloud Storage |
| `PropertiesService` | Firestore `_meta/props` |
| `LockService` | 每次請求一份快照，寫入批次回寫 |
| `Utilities` / `Session` | `functions/shim.js` |
| 網頁由 `doGet` 送 | Firebase Hosting 送 `public/index.html` |

### 怎麼做到不改邏輯

`Code.gs` 裡所有資料存取都只走四個原語：`readRaw_` / `writeTable_` / `appendRow_` / `upsert_`，而 `SpreadsheetApp` 只出現在一個函式裡。`functions/index.js` 把整份 `Code.gs` 載進 `vm` 沙盒，再把這四個換成 Firestore 版本，其餘照舊。

同步／非同步的落差這樣解：請求進來先把資料表載成記憶體快照 → 同步跑 API（它看到的跟在 GAS 上一樣是陣列）→ 回傳後批次寫回。表格版本號放在 `_meta/versions`，沒變動就重用快取，省 Firestore 讀取。

### 檔案

```
functions/index.js      進入點：一支 HTTPS Function 依名稱分派 48 支 API
functions/store.js      Firestore 資料層
functions/shim.js       Google Apps Script 全域的替身
functions/selftest.js   不連 Firebase 的 34 項自我測試（node functions/selftest.js）
firestore.rules         前端一律不能直接碰資料庫，全部要過 Function
storage.rules           同上
build-web.js            產生 public/index.html（正式）與 public/demo/index.html（展示）
```

### 部署

```bash
node patch-tpl.js && node build-gas.js && node build-web.js
cp gas/Code.gs functions/Code.gs
firebase deploy
```

推上 GitHub 的 `master` 會由 `.github/workflows/deploy.yml` 自動做完以上全部，並在部署前先跑一次後端測試。需要兩組 repo secret：`FIREBASE_SERVICE_ACCOUNT`、`FIREBASE_PROJECT_ID`。

### 兩個網址

- `/` 正式版：真的收資料，後端走 `/api`
- `/demo` 展示版：假後端跑在瀏覽器裡，每個訪客自己一份沙盒，不會碰到正式資料

### 安全

`firestore.rules` 與 `storage.rules` 都是全拒。前端拿不到資料庫，任何讀寫都要經過 Cloud Function，130 道檢查留在後端——跟 Apps Script 版的安全模型一模一樣。

## 十一、試用班（沙盒班級）

研究者自己要試流程時，把班級設成**試用班**，這一班的資料就**不會進研究紀錄**——R-01～R-08 讀不到，匯出也不含。功能完全一樣，該擋的還是照擋，只是研究面把它整批排除。

- **開班時**：在「開一個班」旁邊按「設為試用班」再開。
- **開好之後**：班級列 → 編輯 → 「設為試用班」，隨時可以切回正式班。
- **切回正式班之後**，那一班之後產生的資料就會進紀錄（先前的也會重新出現，因為排除是讀取時算的，不是刪資料）。

試用班在**學生端與老師端底部會有一條斜紋橫幅**寫著「這一班怎麼點都可以，資料不會進研究紀錄」，避免有人以為自己交的東西被記錄了。

> 排除的實作是在 `apiResearchSlice` 把試用班的組別整批濾掉（`subLog` / `revLog` / `readLog` / `teams` 四處）。`apiExportCsv` 是從這一份衍生的，所以匯出自動同步乾淨。

## 十三、老師可以改這一層的拆分（一組一份）

系統預設的拆分（專案定義、任務拆分…）只是預設。**每一組的專案不一樣，說法也可以不一樣**——在 **T-05 的「這一層的拆分」**先選要改哪一組，再逐塊改：

- **你要叫它什麼** — 換成他自己的工作名稱（例：專案定義 → 題目確立）
- **你的說法** — 學生點開那塊礦石時看到的說明

改完之後，**只有那一組的學生**看得到新名稱；別組完全不受影響。組別按鈕上會標「改了 N 塊」，一眼看得出哪幾組被客製過。

- **礦石本身不變**（定名石、裂晶那些是遊戲物件，是收藏品的名字）
- 資料在 ，主鍵是 
- 兩個欄位都留空＝那一組改回系統預設
- 學生端的地圖、任務清單、圖鑑、S-06 全部自動跟著改（套用只做在  一個地方）
- 老師如果已經替那一塊開了任務，地圖上顯示的是**他的任務標題**；拆分名稱是還沒開的那些格子在用的

## 十四、發任務可以指定組別

T-05 開任務時多一個**「這一項要發給誰」**：預設**全班**，也可以只勾某幾組。

- 沒被指定的組**看不到**這一項，**關卡也不會被它卡住**
- 選滿全部組別＝存成「全班」，不會留下一份會過期的名單

### 礦脈變成「每一組各自四格」

這是這個功能最關鍵的一點。礦脈原本是全班共用一份，加上指定組別之後改成**以組為單位**：

> 甲組專屬的一項佔的是**甲組的**那一格，乙組那一格還是空的。所以老師可以替兩組在同一格放**不同的任務**——例如兩組的「使用者調查」做法完全不同，就各開各的。

系統自動配礦石時也照這個規則：只避開**目標組別已經用掉**的礦石。

> **要注意**：如果只替甲組開了某一格，乙組那一格就一直是空的，**乙組會過不了那一層**。T-05 的「這一層的礦脈還有 N 塊沒開」會標出來，補一項給乙組（或改成全班）就好。
