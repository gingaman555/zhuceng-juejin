# 地心圖鑑 v2 · 走得完的原型

照 `地心圖鑑-規格書.md` 重做的一版。**流程走得完，樣子做出來了**——
學生端與老師端全部的入口都在，規則照規格書 03 算，可以從第一層一路走到結局。

不接 Firestore／Cloud Function：後端是跑在瀏覽器裡的假的一份，資料存在 `localStorage`。

## 打開

```bash
node v2/serve.js
```

然後開 http://localhost:8792 。`v2/index.html` 是自足的一個檔案，
點兩下直接開也可以（只有字型會去抓 CDN）。

一進來是**第一組 · 甲**，人在水晶迴廊第三天。上面那條**試用列**可以切身分
（五組學生 ＋ 老師）、把時間往前推一天（看期限與 7 天滾動怎麼變）、整班重來。
試用列是原型才有的，真的上線沒有這一條。

## 三條原則怎麼落的

規格書 00 那三條：

| 原則 | 這一版怎麼做 |
|---|---|
| **沒有不能動的原型** | 沒有覆寫層、沒有模板補丁。每一個畫面就是 `src/` 裡的一支函式，改一句話只改一個地方。`build.js` 只是把 `src/` 併成一個檔，不改任何內容 |
| **一個概念一個來源** | 全部的計算在 `src/20-rules.js`，只在那裡。分數、抽數、期限、停留天數、7 天滾動各只有一份定義，兩端共用 |
| **文案跟規則綁在一起** | 講規則的句子不是寫死的字串，是 `RULES.say.*()` 從數字組出來的。把 `RULES.PASS` 從 100 改成 80，畫面上那句話會跟著變成 80，不會變成謊話 |

第三條有一支檢查在守：

```bash
node v2/check.js
```

擋三種東西——規格書 06「明確不要的」那 23 個詞（礦石、學期第幾週、宣告破法、
畫面代號、第五層⋯⋯）不可以出現在畫得出來的字裡；有人回頭把規則的數字寫死成
字串；以及 `offerTrophies()` 讀到任何跟表現有關的東西（`gave`、`rounds`、
`attempt`⋯⋯）——那一支只要看得到成績，戰利品就從一句話變成一個評價。build 之後跑。

## 三件加進來的事

### 戰利品是「挑」的，不是「發」的

那 24 句「他留下的話」本身就是專案管理教材——尺沒有刻度、鑿子會先壞掉、
扣子扣不緊了、杯子只有一條線、袋子沒有底，講的全是範圍控制、停損、取捨。
問題不在內容，在它們是被發下來的。

現在：**老師放行一層 → 層底那一隻退開，留下 3 件 → 學生自己挑一件帶走。**

- 攤開哪 3 件只跟「這一層還有哪幾件沒拿過」有關，由 `hash(組 ＋ 層)` 決定。
  它讀不到分數、輪數、天數——`check.js` 在守這一條
- 三件一樣重，500 分在放行那一刻就記上了。挑哪一件不影響任何數字，
  只影響帶走哪一句話
- **不可以反過來做**：不能「因為你重交了三次，所以發給你斷柄鑿」。
  那一秒它就從一句話變成一個評價，而這個系統從頭到尾不評價任何人

這是學生在整套系統裡唯一一次做真的選擇，也是挑一句格言＝一次省思。

### 剖面做成時間軸

`剖面` 這一頁：X 是天，Y 是深度。世界觀本身就是一張圖表——往地心挖 ＝
深度對時間 ＝ 一條進度曲線。

畫的全是系統本來就有的時間戳，一個都不必碰作業內容：他哪一天開的（刻痕）、
哪一天按了送出（實心點）、判過（綠圈）、要你們補（紅叉）、期限（虛線）、
放行那一天（金線往下的那一階）。底下六張卡是跨任務看得到的：開啟到第一次交
幾天、一項走幾輪、等他判幾天、交的時候離期限幾天、這一層停留幾天。

**全部是描述，沒有一項是評價，也沒有一項進成績。**沒有「應該長這樣」的線，
也不跟別組比。要組別自主調整時程，他們得先看得到自己的時程。

老師端有同一份（`各組的剖面`），資料一模一樣——因為它是描述，兩邊沒有理由看到不同的東西。

### 合格考量累積成一疊

`他寫過的` 這一頁：老師每判一件寫的那一段字，一件一件疊起來。判過的、
要你們補的、放行的理由、回頭補強的理由，全都留著。

- 送出之前，任務頁上會擺一張「他寫過 N 件判斷，翻一下他上一次是怎麼算合格的」
- 跟圖鑑一樣是**個人的**：換組、換班、換專案都跟著人走
- 要你們補的那幾件也留著——「為什麼還不到」跟「為什麼算合格」一樣有用
- 老師零負擔：那些字他本來就要寫

第十次交件的時候，學生對「合格長什麼樣」的掌握不會跟第一次一樣。這一疊是
整套系統裡唯一真正會改變下一輪的東西。

## 進來就看得到的幾件事

種子是照「五組＋一位老師」種的，所以一進來每一種狀態都有東西可看：

- **第一組（你）** 一進來的第一件事是**挑一件帶走**——霧面者上次退開的時候留了三件，
  他們還沒回來挑。挑完才回到工作
- L1 三項都判過了（老師給 3 / 0 / 4），已經放行過一次。
  L2 有一項被退回、一項還沒交、一項在等老師 —— 任務清單三區都有東西
- **第三組** 在佇列最前面，因為他們**舉手說卡住了**
- **第二組** 停留 11 天，這一層開的都交了
- **第五組** 來了但一次都沒送過 —— 排行榜上它跟第三組長得不一樣
- **學生1 的圖鑑跟那一疊裡有上學期的東西**：上一個專案帶下來的生物、
  自己挑過的那一件戰利品、老師上學期寫的那幾段判斷，都跟著人走，
  但不進這一班的排行榜與地圖

## 兩處跟規格書對不上的地方

1. **L4 的道具**。規格書 01 的表在 L4 那一格寫「—」，但 03 說物品 136 種
   ＝ 108 ＋ 24 ＋ **4 道具**，而且「老師放行一層 ＋1000（道具 500 ＋ 戰利品 500）」
   四層都適用。這一版給了 L4 一件 **熱流導航儀**（沿用上一版原型的名字與說法），
   四層各一件才湊得出 136。要維持「—」的話，136 與 1000 分那兩條要一起改。

2. **老師佇列的進入條件**。規格書 02 老師流程第 2 步寫「一組把這一層目前開的
   **全部勾完**，才排進佇列」。勾選是 0 分的自我紀錄、也不是送出門檻，所以這裡
   照「全部**交出來**」實作（沒有一項還在「還沒交」或「要補的」，而且至少一項在等）。
   舉手說卡住的組不受這個條件限制，一樣排進去而且排最前面。

## 還沒做的

規格書 07「還沒解的」那三件，這一版沒有解，只是把地基留著：

- 四個階段仍然寫死（`11-world.js` 的 `LAYERS`）。要做成可設定就是改那一份
- 往返紀錄已經改成「你們來回了 N 次」的框法，剖面那一頁也把輪數畫出來了，
  但**還沒標出這一次比上一次改寫了多少**——兩份草稿並排躺在那裡，
  系統還沒請學生去看它們的差別
- 判過之後沒有通知。帳號模型裡沒有 email 欄位
- 剖面現在畫的是「一組」的節奏。規格書提到的**組員各自的節奏**還沒有——
  資料模型裡一組只有一個身分，要分到人就得先讓 Checks／Submissions 記下是誰按的
